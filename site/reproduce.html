Reproduce: methods, versions, commands, licences

Everything on these pages comes from the files listed here. Replay mode: the Skala energies were computed once, with the script below, and are stored.

Methods in short

  • System. One proton around a nitrite (NO2) frame, on a polar map: angle 0 to 180 degrees, distance 1.0 to 2.4 angstrom; points whose cheap energy is above 60 kcal/mol are skipped.
  • Points. A coarse grid (10 degrees, 0.10 angstrom, 214 points) and a fine grid (5 degrees, 0.05 angstrom) used only where the cheap map is below 60 kcal/mol (451 more points): 665 Skala-1.1 / def2-SVP energies (665 converged; PBE comparison 663). Median 51 s per point on a CPU.
  • Cheap map. GFN2-xTB (tblite) on every grid node.
  • Estimate. cheap map plus a Gaussian-process fit of (Skala minus xTB) at the revealed points (length 0.3, signal variance 25, noise variance 2, in unit-square coordinates).
  • Barrier. the lowest pass between two named wells (a path that minimises its highest point), minus the energy of the first well. Wells are hand-set search windows.
  • Simulated clickers. Five fixed rules, 40 seeded first clicks each (spaced evenly through the list of stored points), 30 clicks, run through the page's own code (figures/make_simulation.js).

Versions

Skala 2026.9, PySCF 2.14.0, matplotlib 3.11.2, Plotly.js 4.1.1 (MIT, bundled as plotly.min.js), Node.js and Playwright for the page checks. Other package versions are in requirements.txt.

Commands (from the folder that contains index.html)

bash check.sh                          # all checks below in one go
node tools/build_site_data.js --check  # site data and schematic are fresh
node tools/build_pages.js --check      # the six pages are fresh
python3 figures/check_numbers.py       # every number in the paper: 0 mismatches
node tests/run_tests.js                # page tests (needs Playwright)

Limits, stated plainly

  • Replay mode only: no energy is computed live. The page design does not depend on that.
  • The clickers on the demo and comparison pages are simulated by fixed rules. No person has been tested.
  • One small system, one functional and one basis set (Skala-1.1 / def2-SVP). There is no higher-level reference calculation, so a different order of wells in the cheap map is "different from Skala", not "wrong".
  • The map shows where a proton sits. Its barriers are not isomerisation barriers of nitrous acid.
  • The surrogate settings were tuned on the same stored points, so the errors are optimistic. The well windows are hand-set.
